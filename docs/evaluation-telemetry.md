# Collect-only evaluation telemetry

Harbor records numeric telemetry automatically when run with `--collect-only`. Use the normal CLI or the SmolDataEnvs `evaluate` command. Training runs use the training traces and checkpoint metrics.

| File | Contents |
| --- | --- |
| `group-NNNN/attempt-NN.requests.jsonl` | Append-only endpoint and relay events. Join on `relay_id` within the attempt file. Each backend request also has an `endpoint_id` and, when available, its original OpenAI response ID. Rows omit request bodies, tool arguments, and response text. |
| `group-NNNN/attempt-NN.json` | The `efficiency` object includes attempt totals, allocator scope, and Pi tool spans. Failed attempts retain the measurements that reached the collector. |
| `group-NNNN/metrics.json` | The committed group includes the scalar `efficiency` summaries and the existing verifier and collection metrics. Collection peaks retain the high-water mark across request-level peak resets. |
| SmolDataEnvs `measurement.json` and `pairs.json` | Each arm includes the worker's end-to-end `task_seconds` and its attempt summary. The worker times each arm after applying its weights. |
| SmolDataEnvs `summary.json` | The `efficiency` section includes coverage, totals, means, medians, maxima, per-success ratios, and paired changes with 95% source-dataset bootstrap intervals. It reports all paired tasks and shared successes. Per-success resource totals include attempts that received failing scores. |

The backend appends its measurement before returning to OpenEnv. The relay then records the proxy response and its status. A context-clipped request has sampled tokens in the endpoint event and a synthetic budget response in the relay event. An over-context rejection records the rendered length and the HTTP error, with no generation. A call-limit stop has a relay event and never reaches the endpoint. Cancellation and runtime errors can leave fields unavailable, and an abruptly terminated process may leave only its completed journal events.

## Measurement definitions

- **Tokens.** `rendered_prompt_tokens` includes completed tokenization for rejected prompts. `prompt_tokens` and `completion_tokens` refer to requests that began sampling. Completions count returned token IDs including sampled stop IDs. If sampling fails, `observed_sampled_tokens` can still record the yielded prefix, while the complete count stays `null`. LFM3 also measures the reasoning span when the token boundary agrees with its parsed text. Unsupported or ambiguous reasoning counts are `null`.
- **Requests and turns.** `relay_requests` counts observed harness requests, `backend_requests` counts endpoint invocations, and `generation_requests` counts requests that entered sampling. For Pi, `agent_turns` counts model responses persisted in the session. OpenCode reports retained agent turns from the capture and tags the source accordingly.
- **Prefill and decode.** `prefill_processed_tokens` comes from the pinned MLX-LM progress callback. This path builds a fresh prompt cache, so `prefill_reused_tokens` is zero. `prefill_to_first_token_seconds` is host elapsed time through the final prefill callback, after the first sampled token has been evaluated. `decode_seconds` measures the rest of the sampling call. MLX can schedule look-ahead work. These fields measure wall time at existing execution boundaries with no extra device synchronization. Kernel time, FLOPs, and energy remain unmeasured.
- **Other wall times.** `inference_seconds` covers the sampler. Endpoint events also time tokenization, completion formatting, SafeAgents review, and total endpoint latency separately when those phases ran. `generation_relay_seconds` sums relay spans associated with generation. Service and relay wall times have different scopes.
- **Tools.** Original `tool_calls` counts calls on retained agent turns. Pi session data provides additional observed calls, actual executions, errors, and execution milliseconds. A validation rejection has no execution span. A missing result makes execution totals unknown. Pi tool timings may overlap, and OpenCode execution durations are currently unavailable.
- **Memory.** `mlx_active_before_bytes` records the resident allocator baseline. `mlx_peak_bytes` is the process's MLX allocator high-water mark during the request scope. Attempt and group peaks include the intervals between requests. These allocator fields exclude the rest of macOS, Docker, and process-wide unified-memory use.

Completed measurements from older recipes are reused on resume. Their missing telemetry remains `null`, and the summary reports the number of observed attempts for each metric. Interrupted infrastructure attempts have their own journal and remain outside the scored pairs. A paired interval requires complete coverage in its cohort and a defined reference denominator. The bootstrap draws whole source datasets with replacement and preserves both arms within each task.
